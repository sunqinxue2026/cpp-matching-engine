# 基于 C++ 的限价订单簿与订单撮合引擎

C++ Limit Order Book and Matching Engine

基于 C++17、STL 和 CMake 的单标的限价撮合项目。分八阶段开发，当前已完成订单模型、规则设计及第二阶段订单簿与索引，不代表撮合系统已完成。不连接交易所，不提供真实下单。

## 当前状态

第一阶段和第二阶段已验收；第三阶段及以后未开始。验证结果见[第一阶段验收报告](docs/第一阶段_总体架构与订单模型验收.md)及[第二阶段验收报告](docs/第二阶段_订单簿与订单索引验收.md)。测试方案第一阶段采用无需下载依赖的 CTest 契约测试，后续扩展 GoogleTest。

## Linux 构建

需要支持 C++17 的 GCC/Clang 和 CMake 3.20+。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/matching_engine
```

## 订单簿结构接口

`OrderBook`以只读引用关联调用方持有的`OrderStore`，支持`insert`、结构`erase`、最优订单/价格、档位快照和一致性检查。订单表必须比订单簿更晚销毁，活动订单不得外部删除或替换；订单簿禁止复制移动。`erase`不修改订单状态，不代表业务撤单。成功入簿序号必须严格递增；数量溢出明确拒绝，不回绕。尚无OrderManager、撮合、状态流转或成交生成。

本阶段本机Windows Debug编译通过，CTest为2个契约程序通过。Linux第二阶段尚未重跑；第一阶段Ubuntu结果不替代本阶段证据。

## 撮合规则（已设计，尚未实现）

买盘价格降序，卖盘价格升序；相同价格 FIFO。新买单价格 >= 最低卖价、新卖单价格 <= 最高买价时可撮合，成交价采用订单簿中已有的被动方价格。每次对手方匹配生成独立成交；数量取双方剩余数量最小值。剩余有效数量入簿，已成交或已撤销订单不能再次成交。

价格用 int64 整数 tick，不用浮点直接比较。第一版单标的、单线程；不含市价单、改单、费用、持仓账户和网络交易接口。
