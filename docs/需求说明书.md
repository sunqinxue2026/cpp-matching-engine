# 需求说明书

## 1. 项目与角色

中文名称：基于 C++ 的限价订单簿与订单撮合引擎。英文名称：C++ Limit Order Book and Matching Engine。
项目负责人兼学习者：用户；主要开发工程师：FeiBo，承担资深 C++ / 交易系统工程师角色，负责设计、落地、编译、测试、文档与讲解。用户审批业务规则和阶段验收，未经确认不跳阶段。
项目用于学习与初级量化开发、交易系统开发、C++ 岗位面试；公开首页以系统功能与实际完成范围为主。

## 2. 技术和边界

C++17、STL、CMake、Linux、GoogleTest/合理等价测试方案、Git。自研核心逻辑，无第三方交易框架。第一版单标的、单线程、限价订单，不接交易所、不含真实交易接口；多线程仅为后续扩展。不为展示而强行使用智能指针或继承。

## 3. 实体契约

Order：唯一 order_id、symbol、side、整数tick price、quantity、remaining_quantity、sequence_id、status。价格数量正值；ID及序列正值。状态 NEW / PARTIALLY_FILLED / FILLED / CANCELED / REJECTED。已完成、已撤销不得再成交。
Trade：trade_id、symbol、buy_order_id、sell_order_id、trade_price、trade_quantity、trade_sequence。一次对手方匹配一条成交。序列由引擎产生而非调用者控制。

## 4. 业务功能

接收限价买卖单、维护买卖簿、价格优先时间优先、部分与完全成交、连续跨档撮合、剩余量入簿、撤单、订单状态查询、逐笔成交、市场深度。
买盘从高到低，卖盘从低到高；同价 FIFO。交叉条件买价>=卖价；成交价始终是已有被动订单价格。例如卖100tick/100股，买101tick/40股，成交100tick/40股，买FILLED，卖PARTIALLY_FILLED且剩余60。
撤单按ID定位，检查活动状态，移除节点与索引，更新状态并清理空价档。不存在、已成交或已撤销撤单返回明确结果，不改原状态。ID在本进程生命周期不可复用，完成订单历史记录保留，活动位置索引清理。
市场深度包括最优买卖价（空簿为空）、逐价档剩余量汇总及活动订单数。

## 5. 模块与职责

Order、Trade、OrderBook、MatchingEngine、OrderManager、TradeManager、MarketDepth、测试模块。禁止把业务堆在main。OrderBook管理结构；MatchingEngine实施匹配；OrderManager校验和历史查询；TradeManager分配成交序号和留存；MarketDepth只读查询。

## 6. 测试验收矩阵

必须覆盖：正常买单、正常卖单、非法价格、非法数量、不交叉、交叉、价格优先、同价FIFO、完全成交、部分成交、连续撮合、撤未成交单、撤部分成交单、撤不存在单、终态不再成交、空价档清理、索引一致性。还需覆盖重复ID、符号不一致、空簿及算术溢出。
各场景核对相关订单状态、剩余量、成交与订单簿；非法请求检查无副作用。基础契约早期就测试，第七阶段集中扩展，不能等第七阶段才检查正确性。

## 7. 性能与C++要求

基础正确性后，以std::chrono测试1000/10000/100000笔，区分提交、取消、撮合耗时，提交数量、成交笔数及吞吐；披露硬件、编译选项、负载及计时边界，禁止虚构数据。
结合代码讲解封装、const、引用指针、容器、迭代器、RAII、移动语义、所有权和复杂度。智能指针仅在确需动态所有权时使用。多线程不属于首版。

## 8. 八阶段与交付

1总体架构/模型/规则；2订单簿/索引；3提交；4价格时间撮合；5部分完全成交/成交记录；6撤单/深度；7测试与修复；8性能与工程文档。每阶段实际编译运行，验收后才下一阶段。
固定交付11项：目标；新增修改文件；已实现功能；运行命令及结果；数据结构算法公式；方案原因；替代方案；瓶颈优化；面试追问与回答；未完成内容；下一阶段确认事项。每模块还须解释业务、内存、复杂度与容器取舍。
最终须Linux CMake构建通过、全业务功能与测试通过、性能报告和README齐全。Windows验证不代替Linux验证。GitHub只发布经检查源码测试文档和CI，不上传凭据或构建产物。
